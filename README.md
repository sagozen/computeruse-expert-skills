# ComputerUse.Best Skills

Open-source computer-use skills and professional workflows for AI agents, specialists, and capable computers.

Learn from the guides at [ComputerUse.Best](https://computeruse.best), or clone this repository to explore, run, and adapt the complete skill library locally.

> Free computer-use knowledge. Professional workflows. A practical path from expert process to repeatable execution.

## What this repository is

This repository is the open-source home of the skills and workflow resources published on [ComputerUse.Best](https://computeruse.best).

The website provides the most accessible way to browse, understand, and follow each guide. This repository is for people who prefer to:

- Download the complete library.
- Copy skills directly into their own projects or agent environments.
- Study the underlying files and workflow structure.
- Adapt a workflow for their own tools and requirements.
- Track changes through Git.
- Contribute improvements back to the community.

Skills displayed on ComputerUse.Best are continuously reflected here so the public library remains accessible, portable, and reusable.

## Why ComputerUse.Best exists

Computer use becomes valuable when it produces a result that another person can confidently use—not merely when an agent successfully clicks through an interface.

A professional workflow may need to:

1. Understand the required result and acceptance criteria.
2. Inspect inputs and identify missing information.
3. Prepare software, dependencies, permissions, and hardware.
4. Combine interface control with scripts, APIs, and connectors.
5. Add review checkpoints at important stages.
6. Recognize failures and recover safely.
7. Validate the final deliverable before completion.

ComputerUse.Best documents this complete process: the environment, actions, decisions, review steps, failure conditions, and delivery checks that turn a demonstration into a repeatable workflow.

## Get started

### Browse online

Visit [ComputerUse.Best](https://computeruse.best) to explore the library and follow the guides in a reader-friendly format.

### Clone the complete library

```bash
git clone <repository-url>
cd <repository-directory>
```

Browse the available skill directories and open the README or instruction file for the workflow you want to use.

### Download a single skill

If you only need one workflow, copy or download its directory and preserve the included files and structure.

Follow that skill’s own requirements and setup instructions before running it.

## Repository structure

The exact structure may evolve as the library grows. A typical layout looks like this:

```text
.
├── skills/
│   └── skill-name/
│       ├── README.md
│       ├── SKILL.md
│       ├── references/
│       ├── scripts/
│       └── assets/
├── docs/
├── examples/
├── CONTRIBUTING.md
├── LICENSE
└── README.md
```

Not every skill requires scripts, references, examples, or assets. Each skill should contain only what is necessary to understand and reproduce its workflow.

## Skill maturity

A published resource should make its maturity clear.

| Level | Meaning |
|---|---|
| Blueprint | A structured starting point that may require further implementation or testing. |
| Tested workflow | Executed in a documented environment with recorded validation. |
| Reproduced workflow | Independently run on another compatible setup with documented results. |
| Production-ready offering | Used for defined professional work with clear scope, review, and delivery responsibility. |

A workflow should not be treated as production-ready solely because it is publicly available.

## Professional use and human review

Computer-use workflows can accelerate repeated work, but speed alone does not establish quality.

Professional use may still require a specialist to:

- Clarify an incomplete or conflicting brief.
- Review representative intermediate results.
- Detect visual, audio, technical, or semantic defects.
- Decide when to retry, restore a checkpoint, or stop.
- Confirm that final outputs meet the intended requirements.

Always review generated or modified files before delivering them to a client or using them in production.

## Contributing

Contributions that improve the usefulness, reproducibility, and reliability of the library are welcome.

You can contribute by:

- Correcting unclear or outdated instructions.
- Documenting compatibility with another environment.
- Adding reproducible examples.
- Reporting a failure condition or recovery method.
- Improving validation and review steps.
- Sharing a new professional workflow.
- Reproducing an existing workflow and documenting the result.

Before contributing a new skill, make sure it clearly explains:

- What the workflow produces.
- Which inputs it accepts.
- Which environment it expects.
- What users may configure.
- What must remain consistent.
- Where human review is required.
- What failure looks like.
- How execution can continue safely after interruption.

Please read `CONTRIBUTING.md` before opening a pull request.
